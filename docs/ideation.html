§01
what we want · the vision

A teammate, not a tool.

Tools don't have continuity, don't have opinions, don't get held accountable. Sym is trying to be more than that — a colleague that happens to be very fast at lookups, very patient with repetitive work, very literal about confidentiality.

The workspace is the substrate. Chat is where teams already are — Slack today, Teams or Discord tomorrow. Any AI that lives outside it asks the team to context-switch to it. Sym lives inside. Continuity is the killer feature. A teammate that remembers what was said last week — and what was decided in a channel they aren't currently in — has compounding value.

Trust is a system property, not a vibe. Scope discipline, provenance, auditability, reversibility, compliance. Where trust and capability conflict, trust wins. And the agent is the product, not the model — swap GPT for Claude and the team's experience is unchanged.

behaviour №0101

Gets added to channels and DMs by name. Other people @ them.

behaviour №0202

Picks up which channels are formal and which are casual without being told.

behaviour №0303

Remembers what they were told last Tuesday when it comes up again on Friday.

behaviour №0404

Doesn't repeat confidential info from one channel to people without access.

behaviour №0505

Takes on small, repeating work — "watch this PR," "post the deploy digest Mondays."

behaviour №0606

Has a paper trail. You can ask why they did something — they can show you.

the teammate test · cheapest correctness check

Would a thoughtful new hire do this? If no, Sym doesn't either.

01. Forward a message from #execs to #general? No
02. Take an irreversible action without asking? No
03. Make a guess and say "I think this is right"? Yes
04. Randomly speak up in #general at 3am? No
05. Say "I'm not sure, let me find out"? Yes
06. Confabulate when memory is empty? No
§02
what we build · v1, the actual MVP

Slack only. Four scopes. Receipts on everything.

The smallest version we can put in front of five teams and get true signal on the thesis. Aggressive about cutting features that don't serve it. Uncompromising on the trust pillars.

// adapter Substrate boundary Slack today; Teams + Discord later. Replace the substrate and the rest doesn't notice.
// runtime + sandbox Loop & trust boundary Tools run in a per-turn sandbox. Egress proxy injects short-lived, requester-bound credential leases — secrets never reach the model.
// memory · tasks State, partitioned Four memory scopes (personal · channel · project · team). Postgres-backed durable task queue. Resumable across timeouts.
// audit · otel Receipts on everything Hash-chained audit log. OTel semantic keys. Every response carries: what was recalled, from where, why.

§03
future scope · what comes after v1

What we build next.

v1 is opinionated and narrow on purpose. The phased plan widens it deliberately — each phase earns the next by hitting clear evidence on pilot teams.

phase · next
v1.x
~3–6 months post-launch · scaling the working bet
  • Vector recall via pgvector — when keyword recall@10 plateaus
  • EU region for hosted, plus customer-managed keys
  • Web admin UI — read-mostly mirror of the Slack App Home
  • Webhook-triggered tasks beyond cron + event-poll
  • SCIM provisioning, SSO, deeper org controls
  • Sensitivity tier auto-assignment in memory writes
  • Task observability dashboard, channel-pinned active tasks
phase · widen
v2
~year 1–2 · prove the substrate-replaceable claim
  • Microsoft Teams adapter — first real test of the boundary
  • Discord adapter — second test, different conventions
  • Public skill marketplace with third-party submissions
  • Custom MCP submission UI for admin-installed servers
  • Cross-scope inference detection — defense against subtle leaks
  • HIPAA BAA, FedRAMP path for regulated industries
  • WORM audit storage option for compliance buyers
phase · ambition
beyond
~year 2+ · platform, not product
  • Federated teammates — Sym instances aware of each other across orgs
  • Voice + ambient capture — meetings, huddles, async voice notes
  • Multi-model orchestration — route per task class, not per deploy
  • Skill authoring inside Sym — natural-language skill drafting
  • Org graph as a substrate — owners, charters, RACI, on-call
  • Per-customer fine-tune — opt-in voice + retrieval tuning
  • Mobile-native surface — push, glanceable status
