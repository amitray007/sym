# 066. Upgrade Eve to 0.88.0

Status: accepted
Date: 2026-10-29

## Context

Slack made the Slack Code API generally available on 2026-10-28. It gives an agent app a code
channel for each task. Eve 0.85.0 added code channel support (`codeChannels: true`,
`openCodeChannel()`, and `ctx.openCodeChannel()`). Sym was pinned to Eve 0.81.0.

Eve 0.84.0 moved to v27 session events, and 0.87.0 changed more public APIs. No release has code
channels without these changes, so Sym must take all of them.

## Decision

Pin Eve to 0.88.0. This upgrade changes no Sym behavior. Code channels come in a later decision.

The upgrade changes these parts:

1. Dynamic capabilities use `defineDynamic(ctx => value)`. Eve evaluates them before every model
   call, not once per lifecycle event. The persona and playbook instructions read the ledger once
   per session through a session-keyed `ctx.memo`. The connections resolver reads and refreshes
   its rows once per turn through a turn-keyed memo. A memo holds only JSON, so the resolver
   rebuilds the connection callbacks from the saved rows at each evaluation.
2. The spend limit is `limits.sessionUsage`. It still stops at $2 of brain model cost. Continue
   now starts a new $2 window.
3. The Slack renderer handles v27 facts. Quiet turns keep their rules: reasoning and status
   events stay hidden, a `no_reply` call keeps the turn quiet, and reply text or another tool
   call ends it. The final reply still carries the feedback buttons. A failed quiet turn now
   gets Eve's error notice.
4. `onInputResponse` is `onAnswers`. The owner check also knows Eve's code channel route on
   approval buttons (`eve_input:code:<channel>:tool-approval:`). Connection auth uses `principalType` in place of
   `credentialOwner`. Workflow helpers come from `eve/workflow`. The evals read `turn.reply` and
   use `awaitingInput()`.

## Consequences

- A person answers a free-text question, such as Edit's "What should change", through Eve's
  "Type your answer" box. Since Eve 0.83.2, an app with `onAnswers` takes answers only through
  Eve's controls, so the clicker check also covers text answers. A reply typed in the thread
  reaches the brain as a new message and withdraws the open question. For Edit, the job closes
  as "Brief edited" and the brain reads the reply as the requested change.

- Sessions that started on 0.81.0 move to 0.88.0 at their next message. Eve compacts their
  history first, and remembered approvals and spend windows start over. Sym is not deployed yet,
  so no live sessions move.
- Eve 0.87.0 hid some per-turn fields of the Slack state type. The quiet-turn path and the reply
  path still reset three of them through a local type. A later Eve release can rename them without a type error.
