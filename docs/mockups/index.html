Sym: how it looks and flows

Slack mockups and flow diagrams for every idea in the rundown. One rule runs through all of them: an edited message notifies nobody, and a new message notifies you. So Sym puts progress in edits, sends new messages only when you must act or when work is done, and uses plain text whenever a visual adds nothing.

1. The pieces 2. The display rule 3. A code job end to end 4. Quick asks and updates 5. Scheduled work 6. When it needs you 7. Learning 8. Home tab

1. The pieces

Sym's brain runs on Eve on your Dokploy server. Only the Slack route is public. T3 Code on your Mac does the real work in Claude Code and Codex threads, reached over the tailnet. Postgres holds the job ledger, so a job survives a dead Eve session.

Permission prompts below Full access can't be approved over MCP. That dashed line is you, in the T3 app.

2. The display rule

Sym runs every post through one function in code, chooseDisplay(). The model only passes hints from your words. Four questions, in order, pick one of five levels.

Then modifiers apply, in this order. None of them can hide a level 2 "needs you" message.
ModifierExampleEffect
Your words"quick", "just tell me", "quietly" / "show me progress"Forces text / forces a card for this request
Learned preference👎 on an on-call card, or "too noisy""On-call check: text only" saved to memory, used from the next turn
Quiet mode/sym quiet, or 22:00 to 09:00 local timeOnly "needs you" and failures post. The rest waits for the digest
Upgrade during workA text job passes 2 minutesPosts a card: "This is taking longer. Tracking it here."
Downgrade at the endA card job finishesCard collapses to one line, the result posts as text
Shared channel (team phase)Someone else's jobCards only for jobs asked for in that channel. Other updates go to DMs

Who approves what

Layer 1
Facts and preferences. Sym saves them right away and tells you it did.
Layer 2
Playbooks and rules. One click. Loaded from Postgres at the next session, no deploy.
Layer 3
New tools and code. Draft PR, evals in CI, your merge, then Dokploy redeploys.
  • Everything is text, rows, or code you can read and revert. No model training.
  • The weekly message is one ping, even with several proposals.
  • Repeated work: when the same kind of job finished 3 times, the weekly review drafts a playbook from those briefs for you to approve (decision 058).
  • Every chat request shows Start / Not now. Approved schedules start without a click (decision 024). The trust ladder no longer auto-starts jobs; historical trust rows remain stored (decision 071).

Why a Home tab

It answers "what's going on?" without a message. Every row reads from the ledger, so it stays right even after an Eve restart.

  • Someone not on the allow-list sees one line: "Sym isn't set up for you."
  • Lists show at most 10 rows, then "+N more". Only the allow-listed project names appear.
  • If the worker check fails or takes over 3 seconds, the header says "status unknown".
  • Slack's AI side panel and suggested prompts come later. They need raw API calls and may need a paid plan.

9. Code channels

Off unless SYM_CODE_CHANNELS is on (decision 067). When you click Start, the job moves from its thread into its own Slack code channel. The card and result post there, and anything said there is about that job, with no tag needed. Worker questions appear in the current job conversation, including the channel. Say "we're done" to request closure. Sym reports archive success only after confirmation. If Slack refuses the channel, the job stays in its thread. You can also ask Sym to move a conversation into a code channel; a job started there uses it (decision 068).
