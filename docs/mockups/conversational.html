Seven rules

  1. One voice. Every message is in the persona. Code supplies facts and gates; the model writes the words. When no model is available, code has a plain fallback in the same tone.
  2. Talk like a teammate. Lead with the point. Name the work (“the billing retry”), or say “this” in its own thread. Job numbers stay inside the tools. Say what I'm on and what I'm leaving alone. Give details when asked.
  3. Talking is the interface. Any reply in the thread is read by the brain, which decides: chat, steer the running job, propose a follow-up, stop, or stay quiet. No Steer box. No Fix box. Shared-thread addressing still lets Sym stay out of side talk.
  4. Buttons only for choices, access, dismissal, or links. Offer buttons when there are two or more next steps or choices, such as Start / Not now. Every options message still accepts any typed reply. A single button is allowed only for sign-in or authorization, dismissal (Dismiss or Not now on a nudge), or an external link (Open PR #812, Open CI run, Open the job channel). No lone action buttons. No Looks good, Fix, Close, or Steer controls. The agent chooses labels, up to 30 characters each. Code owns the verbs: say, start, approve, deny, stop, dismiss, and open-link. Code binds targets and rechecks who clicked, their permission, and current state. A label never grants authority.
  5. Facts stay exact. The PR link, test truth, and every check concern must appear. The writer weaves them into sentences. If one is missing, code appends a plain sentence. “Tests didn't run” never becomes “passed.” Plain sentences stay the default. Use lists, tables, or a plan only when the content has that shape. No forced tl;dr or “% sure.”
  6. Progress is one working note, edited silently. Use 1-3 sentences: what I'm on, what I found, what I'm leaving alone. Add a tiny muted meta line: 9m · Builder. During a run, new notifying posts come only when you must act, when it's done, or when it failed. Direct answers still reply to the person who asked.
  7. Less chrome. No 👍/👎 on chat replies. Reactions are feedback. No model line in a proposal unless asked. No “Closed by” stamps. No rating buttons on results either. Useful choices and links follow rule 4.

What code still guarantees

  • The Postgres ledger is the source of truth. A dead brain session does not lose the job, proposal, question, or delivery state.
  • chooseDisplay decides post, edit, silence, and target. The outbox requires that decision. Home is a private view refresh, not a Slack post.
  • Approvals and owner-only gates are code-owned and bound to stored payloads and revisions. Every click rechecks actor and job state. Typed approval cannot float to a different proposal.
  • Production and customer data stay read-only. Sym can prepare a change; a person runs it. Repository edits go through Builder, never Sym itself.
  • Required facts stay present: validated PR link, exact test truth, and every check concern. Missing facts get plain appended sentences. Unknown is never success.
  • Every message has a full plain-text text fallback for notifications and screen readers, including required facts and decisions. The fallback works when no model is available.
  • Each model call has a budget and timeout. Writer failure, timeout, or unavailable model falls back to code without delaying required notifications.
  • Untrusted worker text never sets a button's verb or target. Code validates stored payloads, approved scope, URLs, gate revisions, and allowed actors.

Proposal only. A warmer voice keeps the same ledger, approval gates, and read-only production boundary.
