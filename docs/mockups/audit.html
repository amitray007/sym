Proposed job and channel lifecycle

  1. Treat job completion, worker settlement, PR following and channel archival as separate persisted facts.
  2. Keep the channel open after a result while review or follow-up is expected; talk in the channel to request more work.
  3. A person saying “we're done” requests closure. Code checks the latest job, authorization and pending decisions before acting. Offer an explicit confirmation only when the consequence is ambiguous.
  4. A merged or closed PR can propose or trigger closure under an owner-configured policy; do not assume every completed job has a PR.
  5. Idle timeout should prompt or archive only under an explicit policy, with pending questions and active work excluded.
  6. Closure settles the worker thread, stops Sym's PR follow, posts a final summary, then archives the channel. Record each outcome and retry incomplete steps; never claim an external action succeeded before confirmation.
  7. If a person reopens a channel, explain the closed job state and offer a new authorized job; do not silently restart the worker or PR watch.
  8. Replace the permanent Close button with conversation and automatic housekeeping; retain an exceptional retry action only for a real unresolved failure.
